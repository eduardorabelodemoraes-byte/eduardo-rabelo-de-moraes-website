# THE THRESHOLD HANDBOOK

## Operational Protocol

Version 2.0

---

# Purpose

The Handbook defines how the project is conducted.

It does not define identity.

It does not define permanent decisions.

It defines methodology.

Whenever procedural uncertainty exists, the Handbook governs the work.

Identity belongs to the Manifesto.

Permanent decisions belong to the Canon.

Historical knowledge belongs to the Laboratory Log.

---

# Fundamental Principle

Understanding always precedes implementation.

No implementation begins from code.

Every implementation begins from perception.

---

# Sequence of Work

Every phase follows the same sequence.

Understand.

Observe.

Describe.

Hypothesize.

Design.

Implement.

Observe again.

Conclude.

Document.

Only then does the next phase begin.

---

# Beginning a New Phase

Every collaborator begins by reading:

1. Threshold Brief

2. Manifesto

3. Canon

4. Handbook

5. Architecture

6. Glossary

7. Laboratory Log

8. Current Mission

9. Implementation Task

Implementation begins only after these documents have been understood.

---

# Questions

Each phase answers exactly one question.

If multiple unrelated questions appear, the phase must be divided.

Complexity is managed through decomposition.

---

# Hypotheses

Every hypothesis must:

describe a perceptual prediction;

be understandable by an observer;

be capable of confirmation;

be capable of refutation.

If a hypothesis cannot be disproved, it is not ready.

---

# Variables

Every experiment explicitly distinguishes:

constants;

variables;

unknowns.

Only one primary variable should change during a single experiment.

---

# Experiments

Every experiment contains:

Identifier.

Objective.

Question.

Hypothesis.

Constants.

Variables.

Method.

Implementation.

Observer.

Observation.

Result.

Conclusion.

Next Question.

Nothing else.

---

# Observer Protocol

Observers never receive explanations before observation.

Observers never receive expected outcomes.

The first report must always be spontaneous.

Questions asked after observation must remain neutral.

---

# Interpretation

Observation precedes interpretation.

Interpretation never modifies observation.

Historical reports are preserved exactly as recorded.

---

# Conclusions

Every experiment ends with exactly one conclusion.

Supported.

Refuted.

Inconclusive.

No additional classifications are permitted.

---

# Negative Results

Negative results are preserved.

They eliminate possibilities.

They reduce uncertainty.

They therefore constitute progress.

---

# Technology

Technology exists only to implement approved perceptual objectives.

Technology never determines those objectives.

Implementation may change completely.

Perceptual objectives remain.

---

# Code

Code possesses no institutional authority.

Code is replaceable.

Knowledge is cumulative.

---

# Documentation

Documentation is part of the project.

Documentation is maintained with the same editorial standards as implementation.

Documentation always precedes memory.

---

# Canon

Only explicit project decisions enter the Canon.

Experiments never enter the Canon.

Temporary implementations never enter the Canon.

---

# Current Mission

Only one Current Mission exists.

Every completed mission becomes history.

History belongs exclusively to the Laboratory Log.

---

# Prompts

Prompts are temporary operational instructions.

Documents are permanent institutional knowledge.

Whenever possible, knowledge migrates from prompts into documentation.

---

# Communication

Every statement belongs to one category.

Observation.

Inference.

Proposal.

Decision.

Implementation.

These categories must never be mixed.

---

# Completion

A phase ends only when its original question has been answered or explicitly abandoned.

Implementation alone never completes a phase.

---

# Guiding Principle

The Threshold Project values understanding above execution.

Execution without understanding is considered incomplete.
